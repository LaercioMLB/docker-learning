    3. Comunicação em Sistemas Distribuídos

    A comunicação é a espinha dorsal de qualquer sistema distribuído, permitindo a coordenação e a troca de informações entre processos.

    3.1. Fundamentos da Comunicação em Rede

    • Processos: Um processo é uma instância de um programa em execução. É a unidade fundamental para a execução de tarefas em um sistema distribuído.
    • Sockets: São pontos de extremidade para a comunicação entre processos em uma rede. Sua principal função é estabelecer um canal de comunicação que facilita a troca de informações.
    • Protocolos de Comunicação:
      • TCP/IP: Um conjunto de protocolos comumente usado que garante a entrega confiável e ordenada de pacotes.
      • Comunicação Orientada a Fluxo (TCP): Garante que os dados cheguem na ordem correta, sendo mais confiável.
      • Comunicação Orientada a Datagramas (UDP): Não garante a ordem de entrega, mas é geralmente mais rápido e eficiente.

    A principal diferença é que a comunicação orientada a fluxo garante a entrega ordenada dos dados, enquanto a orientada a datagramas não.

    3.2. Falácias da Computação Distribuída

    Ao desenvolver aplicações distribuídas, é crucial não fazer suposições ingênuas. Um desenvolvedor deve sempre assumir que:

    • A rede não é confiável.
    • A latência sempre existe, independentemente do tipo de rede.
    • A largura de banda é finita, com limites impostos pelo hardware e provedores.
    • A topologia da rede pode mudar.

    3.3 Protocolo HTTP

    O Protocolo de Transferência de Hipertexto (HTTP) é o protocolo da camada de aplicação usado para definir como clientes (navegadores) e servidores (servidores web) se comunicam para recuperar páginas da Web. Ele utiliza os serviços do TCP, que é um protocolo confiável e orientado à conexão.

    Conexões: Não Persistentes vs. Persistentes

    • Conexão Não Persistente (Padrão antes do HTTP/1.1): Uma nova conexão TCP é criada para cada requisição/resposta. Se uma página contém 10 imagens, são necessárias 11 conexões TCP (1 para a página principal + 10 para as imagens), o que impõe uma alta carga no servidor.
    • Conexão Persistente (Padrão no HTTP/1.1): O servidor mantém a conexão TCP aberta após enviar uma resposta, permitindo que o cliente envie múltiplas requisições pela mesma conexão. Isso economiza tempo e recursos, pois evita os múltiplos processos de abertura e fechamento de conexão (handshakes).

    Formato das Mensagens

    O HTTP define formatos específicos para mensagens de requisição e resposta.

    • Mensagem de Requisição:

      • Linha de Solicitação: Contém três campos: o Método (ex: GET, POST), a URL do recurso e a Versão do HTTP. O método GET é o mais comum, usado para solicitar um documento. O método POST é usado para enviar dados ao servidor para serem processados.
      • Linhas de Cabeçalho: Fornecem informações adicionais, como o tipo de navegador (User-Agent) ou os formatos de mídia que o cliente aceita (Accept).
      • Corpo: Contém os dados enviados com métodos como POST ou PUT.

    • Mensagem de Resposta:

      • Linha de Estado: Contém a Versão do HTTP, um Código de Estado (ex: 200 para OK, 404 para Not Found) e uma Frase de Estado textual.
      • Linhas de Cabeçalho: Fornecem informações sobre a resposta, como a data (Date), o tipo de servidor (Server) e o tamanho do conteúdo (Content-Length).
      • Corpo: Contém o documento solicitado (ex: o código HTML da página).

    Documentos Web

    • Estáticos: Documentos de conteúdo fixo, criados e armazenados no servidor, como arquivos HTML.
    • Dinâmicos: Criados por um servidor web no momento da requisição, geralmente por um script ou aplicação (ex: JSP, ASP) que gera a página com informações atualizadas, como data e hora.
    • Ativos: Um programa ou script (como um Applet Java ou JavaScript) que é enviado pelo servidor para ser executado no lado do cliente (no navegador), permitindo interatividade.

    Cookies e Servidores Proxy

    • Cookies: Como o HTTP é um protocolo sem estado (stateless), os cookies foram criados para que os servidores possam "lembrar" informações sobre os clientes. O servidor envia um cookie para o cliente, que o armazena e o reenvia em requisições futuras, permitindo funcionalidades como carrinhos de compras e sessões de login.
    • Servidor Proxy (Cache Web): É um computador que armazena cópias de respostas a requisições recentes. Quando um cliente solicita um recurso, o pedido vai primeiro para o proxy. Se o recurso estiver em cache, o proxy o entrega diretamente, reduzindo o tráfego na rede e a carga no servidor original. O proxy atua tanto como servidor (para o cliente) quanto como cliente (para o servidor original).
