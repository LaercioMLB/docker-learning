    7. Ferramentas e Tecnologias Essenciais

    7.1. Balanceamento de Carga com HAProxy

    • O que é? O balanceamento de carga distribui o tráfego de rede entre múltiplos servidores para otimizar o uso de recursos e evitar sobrecarga.
    • HAProxy: É uma ferramenta popular de software livre que atua como balanceador de carga, cuja função principal é distribuir o tráfego entre múltiplos servidores.
    • Algoritmos de Balanceamento:
      • Round Robin: Distribui as requisições sequencialmente entre os servidores, garantindo uma distribuição uniforme.
      • Outros algoritmos comuns são: Least Connections, IP Hash e Weighted Round Robin.

    Exemplo de Configuração no HAProxy: Para direcionar tráfego para conteúdos estáticos (/audio, /images), é preciso criar uma acl (lista de controle de acesso) no frontend e um novo backend chamado static_content. Este backend deve conter os servidores de destino e usar o algoritmo roundrobin. Também é possível ativar o cache com httpcache e definir um TTL (tempo de vida).

    7.2. Conteinerização com Docker

    • O que são Contêineres? Contêineres são ambientes leves e portáteis que empacotam uma aplicação e todas as suas dependências.
    • Vantagem Principal: O principal benefício do uso de contêineres Docker é o isolamento de aplicações e suas dependências, garantindo consistência entre ambientes de desenvolvimento e produção.
    • Dockerfile: É um script usado para construir uma imagem Docker. Para criar uma imagem eficiente e segura, a melhor prática é:
      • Começar com uma imagem base mínima, como o Alpine Linux, para que a imagem seja leve.
      • Adicionar apenas os pacotes e dependências estritamente necessários para executar o serviço.
    • Redes no Docker: Em caso de problemas de comunicação entre contêineres, a primeira ação deve ser verificar se a rede do Docker está configurada corretamente. Para garantir comunicação eficiente e isolamento, a melhor estratégia é criar uma rede Docker personalizada e conectar os contêineres a ela.

    7.3. Monitoramento e Logs com o Elastic Stack (ELK)

    • Importância: A centralização de logs é uma prática essencial em sistemas distribuídos para facilitar o monitoramento e a solução de problemas.
    • Elastic Stack: É uma suíte de ferramentas para coleta, armazenamento, análise e visualização de dados em tempo real. Seus componentes principais são:
      • Elasticsearch: Motor de busca e análise responsável por armazenar e indexar grandes volumes de dados.
      • Logstash: Atua como um pipeline de coleta e processamento de dados, permitindo transformar e enriquecer os logs antes de enviá-los ao Elasticsearch.
      • Kibana: Interface gráfica para visualização e análise dos dados armazenados no Elasticsearch, permitindo a criação de dashboards.
      • Beats: São agentes leves responsáveis por coletar dados de diferentes fontes (como logs e métricas). Atenção: Os Beats enviam dados para o Logstash ou Elasticsearch, não diretamente para o Kibana para visualização. O Kibana lê os dados do Elasticsearch.

    7.4. Qualidade de Serviço (QoS)

    7.4.1. Garantindo a Qualidade de Serviço (QoS)

    Qualidade de Serviço (QoS) refere-se à capacidade do sistema de atender a métricas de desempenho como tempo de resposta, throughput e disponibilidade, especialmente sob alta demanda. Em sistemas de larga escala, como uma plataforma de streaming de vídeo, estratégias eficazes para garantir a QoS incluem:

    • Balanceamento de Carga: Distribuir uniformemente o tráfego de usuários entre diferentes servidores.
    • Cache: Armazenar cópias de conteúdo popular em servidores geograficamente distribuídos para reduzir a latência.
    • Replicação de Dados: Manter cópias redundantes de dados críticos para garantir a disponibilidade em caso de falhas.
    • Agendamento de Recursos: Alocar recursos de computação e rede de forma eficiente para processos críticos.

    Uma estratégia que, embora vise proteger o sistema, NÃO é considerada eficaz para garantir a QoS do ponto de vista do usuário é o Controle de Admissão, pois limita o número de usuários simultâneos, podendo negar o serviço e prejudicar a experiência em momentos de pico.
