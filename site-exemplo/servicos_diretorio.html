    6. Serviços de Diretório

    Serviço de Nomes vs. Serviço de Diretório

    Em um sistema distribuído, recursos como arquivos, impressoras ou páginas web precisam de nomes para serem localizados e acessados.

    • Serviço de Nomes: Sua principal operação é a resolução de um nome, ou seja, dado um nome, ele retorna seus atributos. O exemplo mais famoso é o DNS (Domain Name System), que resolve um nome de domínio (ex: www.google.com) para um endereço IP.
    • Serviço de Diretório: É similar, mas com uma diferença crucial: permite a busca por nomes a partir de seus atributos. Seria como procurar o nome de uma pessoa na agenda do celular sabendo apenas o seu número de telefone.

    LDAP (Lightweight Directory Access Protocol)

    O LDAP é um protocolo de acesso a diretórios. Ele é uma versão mais "leve" e prática do padrão X.500 e roda sobre TCP/IP, o que facilitou sua popularização.

    • Estrutura: As informações em um diretório LDAP são organizadas de forma hierárquica em uma Árvore de Informações de Diretório (DIT). Cada entrada na árvore é composta por um conjunto de pares "atributo: valor" (ex: uid: als, mail: als@dominio.com.br).
    • Nomenclatura: As entradas são identificadas globalmente por um Nome Distinguido (DN), que é formado pela sequência de Nomes Distinguidos Relativos (RDN). Por exemplo: cn=Servidor Principal,ou=Ciência Comp,o=Universidade ABC,c=BR.

    Aplicação em Redes Heterogêneas

    O principal desafio em uma rede com sistemas operacionais diferentes (Windows, Linux, etc.) é a duplicação e inconsistência de informações, especialmente de autenticação de usuários. Se um usuário existe no servidor Linux e no Windows, sua senha precisa ser gerenciada em dois lugares diferentes.

    O LDAP resolve este problema ao centralizar as informações de diretório (como dados de usuários, grupos e computadores) em um único local.

    • Funcionamento: Todos os serviços da rede (servidores de arquivos, impressão, e-mail) são configurados para consultar o servidor LDAP para autenticar usuários e obter informações. Como o LDAP é um protocolo padrão que usa TCP/IP, qualquer plataforma pode se comunicar com ele.
    • Vantagens: Simplifica a manutenção, elimina a redundância de dados e aumenta a segurança ao centralizar o gerenciamento de acesso.

    Segurança e Limitações

    • Autenticação: O LDAP em si é um protocolo de acesso, não de autenticação. Para proteger os dados do diretório, ele é frequentemente usado em conjunto com protocolos de autenticação robustos, como o Kerberos, que usa criptografia forte.
    • Replicação para Tolerância a Falhas: Para garantir a disponibilidade, os dados do diretório devem ser replicados. Implementações como o OpenLDAP oferecem esquemas de replicação como Single-Master (um servidor de escrita, vários de leitura) e Multi-Master (todos os servidores aceitam escritas e se sincronizam).
    • Comparação com Banco de Dados Relacional:
      • O LDAP é otimizado para consultas rápidas e leituras frequentes, enquanto as atualizações são menos comuns.
      • Diferentemente de um SGBD, o LDAP não suporta transações complexas nem controle de concorrência robusto.
      • A representação dos dados no LDAP é estritamente hierárquica, enquanto SGBDs permitem relacionamentos mais complexos.
